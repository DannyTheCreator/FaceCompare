# 人脸比对系统操作手册

## 一、首次运行

在项目根目录创建独立虚拟环境、安装 `requirements.txt`，执行 `python main.py --download-models`，再用 `python main.py --check` 检查依赖与两个 ONNX 模型。检查通过后执行 `python main.py`。

若模型下载受校园网或代理限制，可从 OpenCV Zoo 手动下载下列文件到 `models/`：

- `face_detection_yunet_2023mar.onnx`
- `face_recognition_sface_2021dec.onnx`

不要把Git LFS指针误当成模型。除大小外，程序会校验固定版本的SHA-256，值见 `THIRD_PARTY_NOTICES.md`。手动下载后也执行 `--check`。

## 二、摄像头

1. 接入 USB 摄像头。
2. 从“摄像头 0–5”逐个选择，以实时预览确认哪个是外置设备。
3. 点击“开启摄像头”。状态栏显示设备实际返回分辨率。
4. 设备被占用、读取连续失败或拔出时，关闭占用程序/重新插入，再点击开启。

退出窗口会释放摄像头与工作线程。需要修改候选编号、分辨率或识别频率时，编辑 `config.json` 的 `camera` 段。

## 三、建立标准库

1. 点击“人员录入 / 补充样本”，选择“新增人员”。
2. 输入姓名；内部编号可填学号。数据库使用数值 `person_id` 关联，允许姓名重复。
3. 采集至少 5 张、建议 10–20 张清晰样本，覆盖正面、轻微左右转头和自然表情。
4. 质量门控会分别提示无脸、多脸、过小、模糊、过暗和过亮。过于相似的连续帧会被拒绝。
5. 保存后模板立即更新，无需重启。

为已有人员补样时，在同一窗口选择其姓名，只需至少 1 张合格样本。“标准库管理”可展开人员、预览样本、删除单张样本或整个人员。删除不可撤销，实验前请备份 `data/`。

## 四、识别

- “抓拍识别”：对当前帧执行一次检测、质量检查、特征提取、模板匹配和阈值判别。
- “连续识别”：按配置间隔更新；积压时丢弃旧待处理帧，因此结果年龄不会无限增长。
- 实时画面与右侧识别快照分开，关闭或切换摄像头、变更标准库、结果过期后清除旧结果。有效期由 `camera.result_ttl_ms` 配置。
- 匹配成功：显示姓名和余弦相似度。
- 未知人员：存在合格单脸，但最高相似度低于阈值。
- 无脸/多脸/质量不足：属于处理状态，不能记作未知正确拒识。
- 多脸提示适用于默认单人模式；多人模式会逐脸输出各自状态，录入仍要求单脸。

界面同时显示算法时延和应用入口到结果完成的端到端时延。余弦相似度不是身份正确概率。

## 五、建议现场验收顺序

1. 冷启动、选择外置摄像头并抓拍。
2. 展示至少 3 名人员及各自样本。
3. 让已录入人员识别出正确姓名。
4. 让未录入人员得到“未知人员”。
5. 运行中录入该人员，再次识别出姓名。
6. 演示无脸、多脸或低质量提示。
7. 展示 `experiments/results/` 中优化前后时延与效果表。
8. 重启程序，确认新增人员仍存在且可以识别。

## 六、故障定位

| 现象 | 处理 |
| --- | --- |
| 启动提示缺少 `cv2` / `PySide6` | 激活 `.venv` 并重新安装 requirements |
| 模型不存在或过小 | 重新执行模型下载；检查代理和 Git LFS 指针 |
| 摄像头打不开 | 更换编号、关闭占用设备的程序、重新插拔 USB |
| 所有人都变成未知 | 检查阈值是否过高、当前模型哈希是否与已录特征兼容 |
| 陌生人常被接受 | 用独立未知验证集提高阈值并重新做最终测试 |
| 暗光/模糊频繁拒绝 | 改善现场光照和稳定性；质量阈值只可依据验证数据调整 |
| 更换模型后标准库兼容样本为 0 | 使用新模型重新提取/录入特征，禁止混用特征空间 |

## 七、数据备份与复现

备份前退出程序，再复制数据库、样本、配置和模型清单；WAL模式下不要在运行期间只复制主数据库。实验输出保留清单、预测CSV、汇总JSON、库版本和模型哈希。演示库与冻结测试库使用不同storage配置。

## 八、多人识别与候选解释

开启摄像头后勾选“多人识别 / 跟踪”和“连续识别”。在“识别分析快照”查看带轨迹编号的框，右侧列表查看每张脸的状态；展开一行显示Top-K身份候选。默认最多处理5张脸，连续3次匹配同一身份才确认姓名。

“等待连续确认”表示尚未接受身份，候选姓名只用于解释。不同身份、质量失败或暂时没有检测到该轨迹，会打断确认。库、设备和模式变化会重置相关状态。快速移动或交叉可能发生轨迹换号，不将轨迹号当作身份。

若只执行一次多人抓拍，首次结果通常待确认；同一帧重复点击不增加确认次数。需要连续识别或采集到新的帧。静态合照命令 `python main.py --image group.jpg --multi-face --json` 仅进行逐脸判断。

图表报告使用 `python experiments/report.py predictions.csv --threshold 0.42 --output experiments/results/report`，阈值替换为已锁定值。参照 `docs/EXPERIMENTS.md` 解读指标。

## 九、标准库完整性与异常处理

录入时可填写“拍摄会话”。同一次拍摄使用同一编号，注册、验证、测试不得共用会话；保存按钮会检查编号非空。标准库为空或只有不兼容样本时，主窗口会提示先录入。

标准库管理中的“检查库完整性”仅报告缺图、损坏特征、版本不兼容、越界路径、未引用图片和待清理图片的计数。“重试待清理图片”仅处理已提交的删除记录，不删除未引用文件。文件被占用时先关闭占用程序再重试；删除人员仍需界面确认。

摄像头编号来自配置，并非自动发现结果。关闭后显示等待释放时，等待设备线程结束再重新打开。识别异常会停止连续提交并保留日志原因，修复原因后重新勾选连续识别。主界面的“有效结果”频率是显示端统计；后台识别吞吐使用视频基准。

# 项目提升与开源项目对照

课程要求的采集、建库、识别、界面和扩容已形成完整流程。作为GitHub作品，原先展示主要围绕单人抓拍，辨识度较少。本轮扩展到多人场景、连续确认、候选解释和实验分析。以下为根据官方资料作出的工程建议，不是性能排名。

| 项目 | 官方能力 | 可借鉴方向 |
| --- | --- | --- |
| [DeepFace](https://github.com/serengil/deepface) | 两图验证、库内检索、视频流和模型接口 | 清晰的验证/识别/流入口与候选结果 |
| [InsightFace FaceAnalysis](https://github.com/deepinsight/insightface/blob/master/python-package/insightface/app/face_analysis.py) | 检测后逐脸组织分析 | 同帧只检测一次，逐脸结果与状态 |
| [Supervision trackers](https://supervision.roboflow.com/latest/trackers/) | 检测与跟踪衔接、ByteTrack配置 | 轨迹编号、连续证据与ID切换评估 |

FaceCompare适合定位为“普通CPU、离线运行、未知拒识、多人展示和可复现实验的桌面应用”。本轮沿用固定的YuNet/SFace及原依赖，没有安装或复制以上项目的实现。

## 本轮实现

1. 多人逐脸处理，单次检测、默认最多5张，独立质量、识别与异常状态。
2. 原创轻量IoU关联和连续3次身份确认，变化、失败、缺失及上下文变化重置证据。
3. 单人或逐脸Top-K候选，展示相似度；候选不会自动变成接受身份。
4. 预测CSV生成分布、开放集工作点曲线和场景汇总，保留失败与实际分母。

IoU基线不是ByteTrack，没有运动预测或外观辅助关联。快速移动、交叉可能换号；轨迹号不代表真实身份。连续确认能控制展示行为，但准确率与误接收改善必须实际测量。

## 后续优先级

| 优先级 | 方向 | 验收证据 |
| --- | --- | --- |
| 高 | 真实多人演示及标注视频评价 | 进出、交叉、未知混入，记录ID切换、确认时间和错误姓名 |
| 高 | 专门的1:1双图验证入口 | 独立两图阈值标定、同人/异人测试与质量提示 |
| 中 | 多姿态模板策略与消融 | 相同数据划分对比质心/多模板，重新标定阈值 |
| 中 | 运动预测和外观辅助关联 | 同一标注视频上的ID切换和时延对照 |
| 中 | 模型后端和CPU推理优化 | 同硬件的准确率、FAR、时延及模型条件 |
| 按需 | 专门活体/防照片攻击 | 独立攻击样本的误接收/误拒绝，不能以眨眼提示作证明 |

下一步最有价值的是实际视频与场景结果。在取得结果前，README明确已实现行为和基线适用范围，不写未经验证的“高准确率”或“复杂场景稳定追踪”。
